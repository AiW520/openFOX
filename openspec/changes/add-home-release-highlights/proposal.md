# Change: 首页精选卡片自动同步版本介绍

## Why

首页 FeaturedContent 的五张卡片目前写死在组件中，“创作画布更新”不会随版本发布变化。项目已有 CHANGELOG.md → changelog.json 的发布同步流程，以及构建时注入的 __APP_VERSION__ 和 __APP_CHANGELOG__，可以复用。

## Options

| 维度 | A：完全自动读取现有日志 | B：发布时补充对外简介，首页自动同步 |
| --- | --- | --- |
| 实现复杂度 | 低，复用版本信息和更新日志 | 中，增加与版本关联的结构化简介及校验 |
| 运行性能 | 构建时注入，无额外首页请求 | 构建时注入，无额外首页请求 |
| 扩展性 | 可展示版本、分类条目和详情 | 可扩展标题、摘要、功能截图和对应入口 |
| 维护难度 | 低，继续维护现有日志 | 每次发布多整理一次对外介绍，无需修改首页组件 |
| 潜在坑点 | 日志可能出现英文或技术术语，不能保证适合作为宣传文案 | 简介需要跟随发布维护；缺失时回退到实际日志，避免旧简介冒充新内容 |

推荐先选 A，完成自动同步；重要版本有更精细的文案需求时再扩展 B。不会在浏览器里调用 AI 自动改写，也不会自动生成或发布未经确认的图片。

## Proposed Behavior

- 保留五张卡片和现有轮播布局，将第一张固定的产品指南替换为当前应用版本的更新介绍。
- 角标改为“版本更新”，标题显示“OpenTu v版本号”，摘要来自本版本实际更新；点击后展示版本信息及按功能、修复、优化归类的内容。
- 页面加载新发布的应用资源后自动显示相应版本；本次不新增轮询、强制刷新或更新弹窗。
- 复用现有封面，并保持其装饰用途；不将封面描述为新增功能的实测截图。
- 正式页面不展示 Unreleased、撤回版本或高于当前应用版本的更新。
- 当前版本没有有效日志时保留通用指南，不捏造介绍，也不把旧版本标为本次更新。
- 构建之前同步 CHANGELOG.md 与 changelog.json，解决仅部分发布路径会同步日志的问题；保持发布流程其余行为。
- 条目作为 React 文本渲染，不使用原始 HTML，不导入工作流页面、更新检查 hook 或聊天依赖。
- 手机端沿用现有首页布局，本次不新增手机展示区域。

## Impact

- Affected capability: home-release-highlights.
- Affected code: FeaturedContent.tsx、精选内容样式及测试、现有版本日志同步与构建入口。
- 不新增后端、定时任务、运行时外部服务、生产依赖或本地业务数据。

## Approval

用户在当前会话回复“A”，批准完全自动读取现有更新日志的方案及上述展示规则。
