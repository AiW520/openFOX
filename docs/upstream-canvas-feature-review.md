# 两个画布的上游更新评估

检查日期：2026-10-17。依据 GitHub API 返回的分支、Release、PR 状态和代码差异，并与当前工作区源码逐项核对。本报告记录了候选评估与第一批按功能适配结果；没有整体替换内嵌目录，也没有合并远程分支。

## 对当前项目的建议

建议选择“按功能适配、分批验收”。当前项目有宿主共享模型配置、原生参数、任务恢复、超分、媒体缓存和手机抽屉，不能以替换内嵌目录或整体更新版本号的方式集成。

- 第一批（已实现）：自由画布的参考图 MIME 修复、文本卡片复制和已生成结果恢复；无限画布的定位/浮层/参考选择交互、复制输入连线及存储统计降级。
- 图片结果恢复同属优先工作，但独立交付：先修复“已生成结果的重新下载/插入”语义，再评估 #308 的参数和等待处理；不要把整个 PR 当成一个低风险补丁。
- 第二批：元素列表/缩略图预览；按模型保存默认分辨率、解耦质量与尺寸。这两组分别涉及资源生命周期和模型参数契约，需要单独验收。
- 选配：参考图保真、原地重新生成、多主题、脚本编辑器继续拆包。NewAPI 视频兼容需确认实际渠道；Suno v2 暂缓。

优先级依据是本项目已有缺口和使用频率；“上游已发布”与“适合本项目直接采用”是两个判断。下列复杂度为代码审阅估计，性能收益尚未经过移植后的测量。

## 必须优先保护的本地行为

### 已完成图片任务的重试边界

当前 `useAutoInsertToCanvas.ts:3241` 在“任务 COMPLETED 且后处理 failed”时走 `retryTask(taskId, { allowCompleted: true })`。`task-queue-service.ts:3086` 为图片创建新的提交参数，随后清空 result/remoteId、设置 SUBMITTING 并再次 executeTask。代码表明这条入口存在再次提交生成、因而可能再次计费的风险；本轮没有实际调用供应商验证计费。

适配 #308 时应把“恢复已有结果”和“重新生成”作为明确不同的动作：下载/解码/插入恢复沿用已完成结果，不清掉原结果和渠道身份；结果确实无法取回时保留失败说明，由用户主动选择重新生成。不应将上游新的计时器直接包在本地 retryTask 外就视为完成。

### 复制、覆盖与超分的写回归属

`project.tsx:1260` 的 duplicateNode 展开原节点；复制粘贴也只浅拷贝 metadata。当前 metadata 另有 workflowTasks、videoTaskId、images[].enhancement。已有超分写回会检查图片 ID、请求 ID 和作用域，活动请求的身份关系必须保留或显式隔离，不能随复制/覆盖意外变成两个独立节点共享同一个活动结果归属。

适配时区分可复用的静态素材与活动任务状态：成功素材可共享存储引用，副本获得自己的图片槽位/任务映射；活动任务是否可复制、以何种状态呈现需在实现设计中明确，不能自动再提交生成。原地覆盖则保留旧结果直至成功，并阻止旧生成或超分回调写回新内容。

### 几何恢复与默认界面

`project.tsx:771` 的 ResizeObserver effect 首次拿不到容器即返回，依赖又为空；但项目恢复完成后容器才挂载。修复观察器时还需处理内部首次居中逻辑，避免覆盖恢复的 viewport。参考选择提示当前也位于 InfiniteCanvas 的变换 children 内，居中 CSS 并不等于屏幕固定。

保持宿主画布切换、当前米白视觉方案、手机抽屉和已完成加载优化。多主题不能修改 document 根节点；生成偏好不能改变用户原模型/渠道；新面板不能在首屏预读所有媒体或加载不使用的编辑器。
